# LangChain은 어떤 프레임워크인가?

LangChain은 **대규모 언어 모델(LLM)을 활용한 애플리케이션을 더 쉽게 만들기 위한 오픈소스 프레임워크**입니다. 단순히 모델에 프롬프트를 보내고 답을 받는 수준을 넘어서, 여러 도구와 데이터 소스, 메모리, 에이전트, 워크플로우를 연결해 **실제 서비스 형태의 AI 애플리케이션**을 구성할 수 있도록 돕습니다.

## 핵심 목적

LLM을 이용한 개발은 보통 다음과 같은 문제를 포함합니다.

- 프롬프트를 체계적으로 설계하고 관리해야 함
- 외부 API, 데이터베이스, 검색엔진 등과 연결해야 함
- 대화 맥락을 유지해야 함
- 여러 단계의 작업을 순차적으로 수행해야 함
- 모델 출력을 검증하고 후처리해야 함

LangChain은 이런 작업들을 모듈화하여, 개발자가 **복잡한 LLM 기반 로직을 더 구조적으로 구현**할 수 있게 해 줍니다.

## LangChain의 주요 구성 요소

### 1. Prompt Templates

프롬프트를 재사용 가능한 형태로 정의할 수 있습니다. 예를 들어 사용자 입력, 시스템 지시문, 변수 등을 분리해 관리할 수 있어 프롬프트 작성과 유지보수가 쉬워집니다.

### 2. Models

OpenAI, Anthropic, Google, Hugging Face 등 다양한 LLM과 연결할 수 있도록 추상화 계층을 제공합니다. 덕분에 특정 벤더에 종속되지 않고 여러 모델을 바꿔가며 사용할 수 있습니다.

### 3. Chains

여러 작업 단계를 연결하는 기능입니다. 예를 들어:

- 질문 분류
- 검색 수행
- 검색 결과 요약
- 최종 답변 생성

이런 흐름을 하나의 파이프라인처럼 구성할 수 있습니다.

### 4. Memory

대화형 애플리케이션에서 이전 대화 내용을 기억하도록 돕는 기능입니다. 챗봇처럼 맥락이 중요한 서비스에서 유용합니다.

### 5. Agents

모델이 상황에 따라 어떤 도구를 사용할지 스스로 결정하게 하는 기능입니다. 예를 들어 계산기, 검색, 데이터베이스 조회, 코드 실행 같은 도구를 선택적으로 활용할 수 있습니다.

### 6. Tools

에이전트가 사용할 수 있는 외부 기능들입니다. 검색 API, 사내 문서 조회, 함수 호출, 데이터 처리 로직 등을 도구로 등록할 수 있습니다.

### 7. Retrievers와 Vector Stores

문서 검색, 임베딩 기반 유사도 검색, RAG(Retrieval-Augmented Generation) 구현에 자주 사용됩니다. 벡터 데이터베이스와 결합하면 대규모 문서에서 관련 내용을 찾아 답변을 생성할 수 있습니다.

## LangChain이 주로 쓰이는 분야

- **챗봇**: 대화 맥락을 유지하는 상담형 봇
- **RAG 시스템**: 사내 문서, 매뉴얼, 위키를 검색해 답변 생성
- **업무 자동화**: 이메일 요약, 보고서 작성, 티켓 분류
- **검색/QA 시스템**: 질문에 대해 관련 문서를 찾아 답변
- **에이전트 기반 워크플로우**: 모델이 도구를 선택해 여러 작업 수행

## 장점

- 다양한 LLM과 도구를 쉽게 연결할 수 있음
- 복잡한 작업 흐름을 구조화하기 좋음
- RAG, 에이전트, 메모리 등 LLM 앱의 핵심 기능을 빠르게 구현 가능
- 생태계가 커서 예제와 통합 자료가 풍부함

## 고려할 점

- 추상화가 많아 처음에는 구조가 복잡하게 느껴질 수 있음
- 단순한 LLM 호출만 필요한 경우에는 오히려 과할 수 있음
- 버전 변화가 빠르므로 공식 문서와 예제를 함께 확인하는 것이 좋음

## 한 줄 요약

LangChain은 **LLM을 활용한 애플리케이션 개발을 위한 프레임워크**로, 프롬프트, 체인, 메모리, 에이전트, 도구, 검색 기능 등을 연결해 실제 서비스 수준의 AI 시스템을 구축하도록 돕습니다.
